# GitHub公開前チェック

## 全体像

| 順番 | 確認 | 合格の目安 |
|---:|---|---|
| 1 | 自動テスト | すべて`pass` |
| 2 | 個人データ検査 | 「ありません」と表示 |
| 3 | Git対象確認 | DB、設定、ログが表示されない |
| 4 | 差分確認 | 架空のテストデータだけ |
| 5 | コミット | ここまで合格してから実施 |
| 6 | push | リモート名と公開範囲を再確認後に実施 |

## 実行するコマンド

```text
npm test
npm run check:public
git status --short --ignored
git diff --cached
```

`!!`はGitから除外されている項目です。次が`!!`側にあることを確認します。

- `.test-output/`
- `TickTockTome.app/`
- `.DS_Store`
- DB、バックアップ、設定、ログがソースフォルダ内へ誤って置かれた場合の該当ファイル

## 絶対に公開しないもの

- `ticktocktome.sqlite3`と`-wal`、`-shm`
- `setting.json`
- `integrations.json`と実トークン
- `backups/`、`exports/`、`runtime/`
- 実在する日記、作業履歴、ファイル一覧
- 自分のホームフォルダを含む絶対パス

公開前検査は、危険なファイル名に加え、ソース本文中の実ユーザー絶対パスと保存済み形式のトークンも調べます。ただし万能ではないため、最後は`git diff --cached`を目で確認します。

ローカルGitリポジトリは作成済みですが、コミットとGitHubへの送信はしていません。`.gitignore`だけは、PC全体の除外設定に埋もれないよう明示的に初回コミット候補へ追加しています。
