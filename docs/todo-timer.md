# Todo・PDF参照・タイマーの保存仕様

## スキーマ更新

- `008_todos_and_pdf_references.sql`：Todo、Todoとタグの中間テーブル、アクションのTodo参照、本・論文の基準フォルダIDとPDF相対パスを追加。
- `009_timer_completion.sql`：アクションの実際の完了日時を追加。
- `010_todo_details.sql`：Todoの期限日、1%刻みの達成度、期限検索用インデックスを追加。
- `011_managed_files_and_library_review.sql`：一般ファイルの相対パス管理、Todo・時間割との関連、Todoと資料の関連、未確認状態、BibTeXコード全文を追加。
- `012_action_review_and_tag_archive.sql`：タグのアーカイブ、8分類への移行、予定終了時刻と起動時の終了確認対象を追加。
- `013_action_actual_times_and_analysis.sql`：予定と実績の時刻、実行状態、日別LLM分析の保存先を追加。
- `014_action_timer_target.sql`：タイマー開始時の目標終了時刻を、時間割の予定終了時刻とは別に保存。

## 操作とトランザクション

Todoは名前、複数タグ、期限日、1%刻みの達成度、管理ファイル・本・論文との関連に加え、固有ID、更新日時、版番号、完了・削除日時を持つ。Todo画面では0〜99%を入力し、100%はアクションの完了操作で記録する。時間割への取り込みではTodo ID、現在の達成度、関連資料を引き継ぐ。完了Todoは一覧から除外するが、同期に必要な情報は保持する。

タイマー開始では現在時刻を実績開始、選んだ所要時間から求めた時刻をタイマー目標終了として保存する。時間割に最初からあった予定開始・終了は上書きしない。完了では版番号を確認し、編集可能な実績時刻・達成度・メモを一括更新する。100%未満の場合はTodoへ残すかを確認し、「はい」の場合だけ指定期限で新規作成または元Todoを更新する。終了時刻を過ぎた未処理アクションは予定順に1件ずつ確認し、完了・実行中・未実施を選択する。

時間割の追加は2段階で行う。最初に「新規作成」またはTodoカードを選び、その後に詳細を編集する。Todoを選ぶと名前、タグ、期限日、達成度を引き継ぐ。新しい時間枠は、最後の予定終了時刻（予定がなければ現在時刻）を次の正時へ切り上げて開始し、終了を1時間後にする。

PDFは基準フォルダIDと相対パスを保存する。登録時・開く時に基準フォルダ外へのアクセスを検証する。参照本体はコピーしない。従来の管理アップロードは互換性のため保持する。

## 境界

画面は `/api/v1/todos`、`timer`、`timer:start`、`timer:complete`、`timer-window` を利用し、DBを直接操作しない。更新は既存のOrigin検査で保護する。常駐ウィンドウは127.0.0.1の読み取り専用タイマー状態を取得する。

スマートフォン同期は未実装。Todoの独立保存・競合版番号・完了削除情報を基礎に、将来は認証付き同期アダプターを追加する。現段階でサーバーを外部公開したり、クラウドSQLiteを複数端末から同時更新したりしない。

## 復旧

移行後に問題がある場合はアプリと常駐タイマーを終了し、現DBを退避したうえで移行前バックアップを復元する。復元したDBはその版に対応するソースで起動する。移行後に追加した内容は移行前バックアップには含まれないため、現DBを削除しない。
